   So: upstream tarball + patches/ ≠ this tree, byte for byte. This tree IS the
   fork that was built and verified. (For the record, the shipped 6-patch series
   alone still reproduces the patched *files* of all six patches exactly — §4d.)

2. scripts/ mirrors the checkout's tools/ directory. The scripts resolve
   ROOT=$(dirname $0)/.., so run from this folder they treat
   /home/asdf/Downloads/powerbi as the project root and expect there:
     - prefix/<name>/            the Wine prefix  (absent here — see §5)
     - wine/install/bin/wine     the built fork   (absent here — see §5)
   pbi_env.sh's PBIFORK mode additionally requires the marker file
   wine/install/.wine-build-complete, which only tools/build_wine.sh creates
   (it is the project's own build driver: configure --prefix=<root>/wine/install
   --enable-archs=i386,x86_64 --disable-tests, make, make install, touch marker).
   build_wine.sh is NOT part of this folder; the README's §1 build steps replace
   it. Per the README, §2–§4 commands are run from powerbi-linux/, which already
   has the prefix, the fonts and the built fork; scripts/ can be copied into its
   tools/ (that is also why scripts/winapi/ exists — pbi_occl_report_shim.sh
   stages it from $ROOT/tools/winapi/bin/wvexstyle.exe).
   install_pbi.sh reads the installer from the absolute path
   /home/asdf/Downloads/PBIDesktopSetup_x64.exe.

3. Build requirements for the tree as shipped: a C toolchain, pkg-config, and —

   it either) — bison and flex. Patch application is not needed: the patches are
