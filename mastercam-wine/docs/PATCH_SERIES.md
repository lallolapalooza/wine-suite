# Mastercam 2027 on Wine — patch series reference

> Scope: the 19 patches applied in order from `patches/series/0001…0019` (the AutoCAD-on-Wine 14 + Power
> BI-on-Wine 5 base requested for this project). Sources: each patch's own commit message; where a patch
> carries no message (0001, 0002) the symptom comes from `acad-wine-main/README.md` and
> `autocad2027-private-main/FINDINGS.md`. `patches/local/` is empty at the time of writing.
>
> The "Mastercam?" column judges a **native-x64 CAD/CAM app with an MSI installer, .NET 4.8 and CodeMeter
> licensing**. `[INFERENCE]` marks judgements that are reasoned from the app profile rather than measured on
> Mastercam.

## 2. Install-time vs run-time

**Matter for installing** (msiexec, install bootstrappers, custom actions, crypto/certificates, MSI):

- **0013 msiexec command line** — direct hit: Windows-rule parsing of `INSTALLDIR=…\\` style properties. The single most install-critical patch.
- **0014 ntdll/actctx privatePath** — the `setup.exe` bootstrap cannot even start if it ships private SxS assemblies.
- **0001 wintrust BLOB/timestamp** and **0006 crypt32 stores** — signature/certificate-store operations during install and driver installation (CodeMeter driver package).
- **0002 kernelbase RegLoadAppKey** — only if the installer devirtualizes MSIX/`.adix` package hives; not expected for a plain MSI.
- **0004 services session 0** — installing/starting the licensing service and having the SCM see it as RUNNING.
- **0007 completion ports**, **0009 missing exports**, **0012 identity**, **0016 impersonation**, **0018 SSPI** — probable in installer custom actions / bootstrap code.
- **0005 Windows hosts file** — installers often write host entries for local licensing/UI.

**Matter for running** (the app once installed):

- **0003 urlmon res zone** (WPF `res://`), **0015 wintypes WinRT metadata** (.NET type resolution) — .NET 4.8 UI.
- **0004 services session 0**, **0005 hosts file**, **0012 identity**, **0017 SPNEGO**, **0018 LsaFreeReturnBuffer** — the licensing/service/auth stack (CodeMeter, network licensing).
- **0008 fd-backed pipes**, **0009 missing exports**, **0010 NS_NLA** — embedded Chromium/WebView2 UI (installers *and* licensing UIs).
- **0011 winex11 BadWindow** — general GUI stability for the main app.
- **0007 completion ports**, **0016 NtImpersonateAnonymousToken** — background/child processes.
- **0019 oledb32** — only for OLE DB data consumers.

## 3. Obvious gaps (stubbed/wrong in these projects, not fixed by the series)

1. **DirectComposition is entirely unimplemented.** `DCompositionCreateDevice`/`2`/`3` return `E_NOTIMPL`. Chromium/Electron logs it and falls back, usually non-fatally; any app needing real composition gets nothing.
2. **No compositor / window-occlusion handling.** Wine has no DWM; Chromium GPU/DXGI surfaces present out of band and occluded windows are not culled. Power BI needed a host-side shim (`wvexstyle.exe hide/redraw`). WebView2-hosted CAD UI can show blank/overlaid panels.
3. **Wine ships no `WinMetadata` (`*.winmd`).** Patch 0015 makes WinRT metadata *resolution* work, but the metadata files must still be copied into `%SystemRoot%\System32\WinMetadata`.
4. **Crypt32 decoder gaps for Authenticode structures.** `CryptDecodeObjectEx` for `SPC_INDIRECT_DATA_OBJID` is unsupported, and `WTHelperCertCheckValidSignature` is a stub returning `S_OK`.
5. **`RegLoadKey` still cannot load Windows binary `regf` hives** — only `RegLoadAppKey` was patched.
6. **NCrypt gaps**: `NCryptOpenKey`/`Decrypt`/`DeleteKey`/`EnumKeys` return `NTE_NOT_SUPPORTED`; `NCryptProtectSecret` family are bare stubs; missing `NCRYPT_SILENT_FLAG`.
7. **`WSALookupService*` beyond `NS_NLA`** are still stubs.
8. **Embedded Chromium needs software painting.** WebView2 under Wine only paints reliably with `--disable-gpu`; the documented flag channels are dead under Wine; WebView2 must be deployed from the NuGet runtime tree (Evergreen installer cannot run).
9. **WPF requires real .NET Framework 4.8**; wine-mono cannot run WPF. A .NET 4.8 app needs `winetricks -q dotnet48`.
10. **Node/libuv on fd-backed pipes** was the underlying Electron failure; patch 0008 addresses the specific calls, but acad still lists `AdskAccessUIHost.exe` stdio (`EBADF`) as unresolved.
